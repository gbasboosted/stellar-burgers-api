# Stellar Burgers API

Автотесты API: задание 2 дипломного проекта. Используются `pytest`, `requests`
и `allure-pytest`. Проверяются только регистрация, вход и создание заказа.

Стенд: https://stellarburgers.education-services.ru/.
[Документация API](https://code.s3.yandex.net/qa-automation-engineer/python-full/diploma/Api-Stellar_Burgers.pdf).

## Установка и запуск

Python 3.10 или новее, команды из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest
```

В Windows активация: `.venv\Scripts\activate`.

По умолчанию каждый запуск очищает `allure-results/` и записывает туда новые
результаты. Доступ к учебному API обязателен: это настоящие HTTP-запросы без моков.
Каждый запрос ограничен таймаутом 30 секунд, автоматических повторов нет.
Настройки можно переопределить переменными окружения:

```bash
STELLAR_BURGERS_URL=https://stellarburgers.education-services.ru \
STELLAR_BURGERS_TIMEOUT=30 python -m pytest
```

## Сценарии

Всего **24 тестовых случая** с параметризацией:

| Группа | Проверки | Количество |
| --- | --- | --- |
| Создание пользователя | Уникальный пользователь; дубликат; каждое из полей `email`, `password`, `name` отсутствует или пустое | 8 |
| Вход | Существующий пользователь; неверный email; неверный пароль; оба поля неверные | 4 |
| Создание заказа | Один ингредиент или состав бургера; пустой список или отсутствие поля; два варианта некорректного хеша. Каждый вариант с авторизацией и без неё | 12 |

Успешные ответы проверяются по статусу, `success` и значимым полям: данным
пользователя и наличию токенов либо названию и номеру заказа. Ошибки проверяются
по точному коду и сообщению из документации. Для некорректного хеша проверяется
HTTP 500: формат тела этой ошибки документация не фиксирует.
Создание заказа без авторизации разрешено API и ожидает HTTP 200.

Тестовые пользователи получают уникальный email с UUID. Фикстура удаляет созданные
аккаунты после каждого теста, включая упавшие проверки; ошибки очистки видны
как ошибки teardown. Токены передаются только нужному запросу, а не сохраняются
в заголовках сессии. Анонимные сценарии не создают пользователя.

Актуальные хеши ингредиентов загружаются из каталога один раз за сессию.
Получение каталога и удаление пользователей используются только для подготовки
и очистки. Другие эндпоинты не тестируются. Документация не содержит метода
удаления заказов, поэтому созданные заказы остаются на учебном стенде.

## Allure

В `allure-results/` сохраняются результаты последнего прогона: названия тестов,
шаги, запросы, ответы и окружение. Пароли и токены в JSON-вложениях скрываются.
HTML-отчёт находится в `reports/allure/index.html` и открывается как обычный файл.

### Сохранённый прогон

23 октября 2026 года локально выполнена команда
`STELLAR_BURGERS_TIMEOUT=5 python -m pytest --tb=short`.
Все 24 случая получили статус **broken** в Allure из-за таймаута TLS при
подключении к учебному стенду (`requests.exceptions.ReadTimeout`). Pytest
показал 11 ошибок в телах тестов и 13 ошибок подготовки данных.
HTTP-ответы не были получены; соответствие поведения API документации этим
прогоном не подтверждено. Ошибки не скрыты через `skip` или `xfail`.

Для повторной генерации установлен Allure Report 3; нужен Node.js 22+ и pnpm 11.25.0:

```bash
pnpm install --frozen-lockfile
pnpm run report
```

Отчёт собирается в один HTML-файл и не требует Java. Сырые результаты также
совместимы с Allure 2, если его CLI уже установлен:

```bash
allure generate allure-results --clean -o allure-report
allure open allure-report
```

GitHub Actions запускает тесты при push в `develop2`, при pull request в `main`
и вручную. Даже при падении тестов workflow генерирует отчёт и сохраняет его
вместе с результатами в артефакт `allure-report` на 30 дней.

## Структура

```text
api_client.py          # HTTP-клиент и вложения Allure
conftest.py            # Подготовка данных, удаление пользователей, окружение
helpers.py             # Уникальные данные и скрытие секретов
urls.py                # Адреса эндпоинтов и настройки
tests/                 # Регистрация, вход, заказы
allure-results/        # Сырые результаты последнего прогона
reports/allure/        # Готовый HTML-отчёт
.github/workflows/     # Запуск тестов и сборка отчёта в CI
requirements.txt       # Python-зависимости
package.json           # Версия и команда запуска Allure CLI
pnpm-lock.yaml         # Зафиксированные зависимости Allure CLI
```
